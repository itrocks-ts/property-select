## Delivered contract

The public `RelationshipGraph<T, C>` accepts the complete path set for projection, criteria and ordering. It sorts
and deduplicates full paths before allocation, reuses shared prefixes and keeps same-type paths distinct. Its public
`GraphPath` exposes final property metadata, owning alias, parent path, target type, accumulated multiplicity and
optional ancestry. Relationship nodes expose physical `Join` steps plus copied/frozen logical and physical facts.
A physical link step deliberately has no domain table definition. The target step retains the logical target type.

New optional dependency hooks `multiplicityOf` and `relationshipOf` preserve existing complete dependency records
and partial bindings. Their defaults reuse existing scalar/collection/component/naming hooks. Physical mappings
support direct, inverse and two-step link relationships. The existing `Join` renders every step through its dialect
hook. Optional ancestors force downstream left joins, including required descendants. Invalid/unknown paths,
prototype-inherited names, ambiguous targets and incomplete mappings fail during planning, before rendering SQL.

The incremental `Joins` API retains its registration order and direct/collection semantics. Explicit aliases now
reject duplicates, including the root alias; generated aliases skip previously supplied explicit aliases.
The additive graph gives S06 a complete immutable path plan without changing the existing builder's public `Joins`
property or invalidating aliases already handed to legacy clients.

The public `@itrocks/framework/sql-relationships` subpath exports binding and schema override hooks without server
bootstrap. Main `bind()` calls the same `bindSqlJoins()` exercised by the tests. Reflection enumeration uses declared
type metadata without constructing domain records. `resolvePropertyPath` supplies multiplicity; relation facts supply
nullable/optional targets, inverse/cardinality and ambiguity. Required metadata cannot override optional type facts.

Explicit inverse identities resolve a target property name or exact `TargetClass.property`. A unique
`Component`/`Composite` pair supplies undeclared inverse/cardinality facts; missing/ambiguous facts remain explicit.
N-N mapping reuses the public MySQL link-table naming function and existing renamed-store foreign-key convention.
`sqlRelationshipsDependsOn({ mappingOf })` supplies custom physical schema facts. Self links, colliding conventional
link columns, arbitrary inverse catalogue ids and inverse 1-1 relationships without ownership require that mapping.
Tests exercise both a self link and a singular inverse override; no physical table names are guessed by a selector.
