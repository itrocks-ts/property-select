## Reproduced defect

The [original V4 replay](../evidence/V7/state-integrated/results.json) receives the expected 410 but times out waiting
for the session-ended instruction. The new [eight-case reproducer](../evidence/V7/session-regression/results.json)
confirms both revoke and expire at all four dimensions using acquired production PUT requests and real file sessions:

- Expected visible text: `The selector session has ended. Reload the page.`
- Observed text: `Unable to save selector state. Retry`, plus ordinary search status.
- Actual Retry: HTTP 410 again. Query and exact columns are preserved; the old durable state remains absent.
- Eight missing-guidance assertions fail; all other 50 assertions pass, including trusted input and no page errors.

[Landscape expiry capture](../evidence/V7/session-regression/844x390-expire-ended.png) and
[portrait revocation capture](../evidence/V7/session-regression/390x844-revoke-ended.png) show the generic Retry.
Before/after screenshots for all eight cases and network/console observations are retained. The 410 console errors
are expected injected-session responses. Separately, [network review](../evidence/V7/session-regression/health-review.json)
remains **FAIL**: 20 ERR_ABORTED events lack captured product AbortSignal attribution in this focused reproducer.
None is waived as expected; the independent retest must attribute or fix them. No global browser-health PASS is claimed.

Source diagnosis: the generic view excludes `persistenceError` from operation status, then `renderPersistence()`
discards its supplied message. List's `HttpStateStore` still supplies the correct recovery instruction. The L7 error
separation therefore regresses the V4 session-recovery presentation. Fix generic rendering safely as text while
preserving the independence of operation errors; HTTP/session policy stays in list. See the complete
[defect and correction boundary](../defects/V7-01.md).
