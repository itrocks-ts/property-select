## Delivered public contract

`Select.buildProjection()` returns the parameterised query, root identity alias, ordered column descriptors and
final public `RelationshipGraph`. The graph supplies target and final property metadata to the future adapter.
Every query path is registered before rendering: selected fields, object expansion, criteria and ordering.
Metadata discovery uses public graph/column enumeration; those preliminary graphs never render SQL.

Object expansion includes direct scalar fields by default, or explicit relative fields including nested singular
paths. A terminal object field expands its identity and direct scalars. Identity-only objects and empty root
selections work. Hidden identities distinguish absent relationships from null terminal values; nested object
boundaries receive their own identities. Overlapping object/scalar selections share output aliases and metadata.
No business record is constructed, read, converted or formatted by this builder.

`ProjectionQuery<C, T>`, `ProjectionColumn<C>`, `ProjectionField<C>`, `ProjectionOptions`, `ProjectionError` and its
code type are public. Scalar field relative paths are empty; object identities are `id` or e.g. `country.id`.
`presence` is ordered from the earliest ancestor. Reserved output aliases `p0`, `p1`, … are independent of table
aliases; low-level explicit aliases remain supported by `build()`. Projection rejects explicit aliases and duplicate
paths. Storage identities are supported without declared model `id` properties.

`objectFieldsOf?: (tableDefinition: T) => readonly string[]` is an optional narrow metadata port, typed through the
second generic of `Dependencies<C, T>` and `sqlBuildDependsOn<C, T>()`. Complete existing dependency records remain
valid. Its default reuses public `Joins` enumeration and `RelationshipGraph` classification; unmapped relations and
plural properties are excluded from default scalar expansion. Framework bindings can exclude nonstored fields.
No private import or copied reflection/type parser is introduced.

`Where.buildGraph()` supplies the common count/projection predicate compiler. It shares equality/null/trusted function
operators with the existing `Where.build()`. A plural prefix opens one correlated `EXISTS`; conditions sharing it
constrain the same row. Independent branches use separate scopes, nested plural paths use nested scopes, and N-N
link steps require an existing target. Null within a plural scope requires a related row. Outer FROM contains only
singular joins; optional ancestry remains left joined. `Count.build()` counts roots using these same predicates.

Ordering supports scalar values and singular object identities, appending root id unless explicit. Limit/offset are
bound nonnegative safe integers, including zero; offset without limit rejects. Root ids are deduplicated, bound and
intersected with criteria; an empty list means no rows. Plural projection/sorting and unknown multiplicity reject
before SQL execution. `Select.build()` retains its low-level wildcard, explicit-alias and joined-row behaviour.
