## Implementation and ownership

`Mysql.select()` calls public `Select.buildProjection()`, executes one parameterised query and returns the neutral
storage descriptors/cells. MySQL's dedicated reconstruction helper creates objects with target prototypes, without
constructors/defaults, and uses one identity map per result. Identities are allocated before conversion; selected
raw sibling fields are available to each local final-property read callback. Shared identities merge fields, and
conversion is reused for overlapping object/descendant selections. Safe bigint identities become numbers; larger
identities retain bigint precision.

Absence uses hidden relationship identities; null fields remain separate. Async conversion, ignored fields,
loaded undefined and error causes/path context are exercised. Object cells list actual loaded fields, excluding
ignored fields and absent nested values. Identity-only and nested object expansions are supported. No graph or
per-cell database read occurs during reconstruction or representative output.

Selection, full entity search and count share `prepareCriteria()` and the public builder's graph predicates.
Scalar operands use the final owner's save callback; object operands use identity without invoking persistence.
Trusted function operators survive operand conversion without mutating caller objects. Full search still constructs
entities and relation-id fields and retains legacy zero-limit/unknown-option handling. Selection validates typed
options, normalises paths, rejects duplicates/plural projections, and intersects bound ids with scope criteria.

The public framework `sql-projection` subpath exposes `bindSqlProjection()` without server bootstrap. Main `bind()`
uses it for the existing SQL/READ and SQL/SAVE callbacks and graph naming. Reflection path errors are translated at
the SQL metadata boundary. The builder's default stored-scalar discovery is sufficient for these metadata owners.

Protected MySQL `querySelection(query, types)` is the narrow execution hook. The maintainer overrides it through
its existing asynchronous context mechanism, retaining deduplicated root/related types for select/search/count.
Concurrent requests preserve distinct contexts. Recovery visits every graph type, including after an earlier
successful modification, and resolves conventional link tables within larger contexts. Real select and count both
repair a missing synthetic table. The [focused regression](../evidence/S07/maintainer-regression.md) records the
multi-type defect, correction and passing retest.

SOLID review: storage owns neutral results, SQL owners own queries/joins, MySQL owns execution/conversion/hydration,
framework owns composition, and maintainer owns schema recovery. No SQL or hydration moved into list/selector.
All cross-owner imports use public entries. Existing callbacks remain partial-bindable, unsupported adapters retain
the rejecting default, and the execution hook preserves adapter substitution without a reverse dependency.
