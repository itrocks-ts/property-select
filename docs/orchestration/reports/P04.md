## Repaired findings

1. **Premature gate requirements.** S07/VSQL required all SQL cases although SQL-14 includes the future list browser
   linkage. L1-META included persisted restoration before L4; V3/T11 and V4/T15 included later drag; V2-HOME demanded
   the future list header control. The new [stage obligations](../VALIDATION.md#stage-obligations) allocate concrete
   observations to their earliest executable gate. Every card links them. Combined case verdicts remain NOT_RUN until
   all observations pass; no acceptance criterion is removed. PORT-04 table and PORT-06 search owners are explicit.
2. **Real session persistence and concurrency.** Per-key locking cannot protect a whole-session file write against
   another key, list save, response autosave or revocation. Inspection also found that FileStore retains live session
   objects in its module cache; a nested mutation can compare equal to that cache and skip the durable write. An
   independent public-API probe reproduced revision 2 in memory but revision 1 on disk. L4 now owns the narrow
   transaction/generation/snapshot changes in `fastify` and `fastify-file-session-store`, with framework composition.
   L4/V4 use Astra/high, existing owner suites and actual HTTP/durable-restart assertions. The existing product defect
   is deliberately unfixed in this documentation task; it is a mandatory L4/V4 acceptance case, not a delivery waiver.
3. **State removal race.** Removing a record must retain its incremented revision until session end. StateRecord now
   permits a tombstone, and read/remove return its revision so old writes cannot recreate removed state and new mounts
   can write using the current revision. PORT-08 covers removal/recreation alongside expiry and concurrent writes.
4. **Scalar conversion ambiguity.** Object loaded fields covered IGNORE, but a scalar cell had no corresponding state.
   ProjectionCell now explicitly represents an ignored/unloaded scalar, distinct from loaded undefined, null, absent
   relation and conversion error. SQL-07 and list rendering cover it; no lazy cell read is introduced.
5. **Commands and handover.** S02 named two different test files; it now uses one deliverable consistently. S03 includes
   the required reflection test build. Table-changing tasks execute the complete existing table suite. The fixture
   bootstrap names the actual public `beforeFrameworkRun` hook. Current checkpoint, owner mappings, model choices,
   plan approval and matrix state are synchronised.
