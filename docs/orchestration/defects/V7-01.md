Status: **OPEN / P2**. Owner: `@itrocks/property-select`, browser persistence presentation.
Affected: T16, STA-03, DEP-05, PORT-08/09 and QUA-01. Final V7 acceptance and D8 are blocked.

## Diagnosis and correction boundary

`src/front/property-select.ts` excludes `selector.persistenceError` from `operationError` in its event subscriber.
Its `renderPersistence()` then renders a generic message and Retry without the actual error message.
The public `HttpStateStore` in list still supplies the correct 410 guidance. The generic browser view discards it.
This is introduced by the L7 error-separation correction; the old V4 recovery behaviour is no longer preserved.

Keep independent operation and persistence messages. Present supplied persistence recovery information safely as text,
with a deterministic fallback for unknown failures, without adding HTTP/session-specific logic to the generic view.
Do not restore the old bug where storage saves erase a failed column operation. Preserve failure query/branch/recents,
state conflict handling and recovery clearing. Add meaningful public view regression tests and actual 410 browser proof.

`FIX-V7-1` performs the owner correction; a distinct `RETEST-V7-1` repeats this reproducer, L7 error preservation and
the entire final matrix on corrected checkpoints before D8. Do not weaken the visible reload-guidance requirement or
accept an unrun touch/session/data case.
