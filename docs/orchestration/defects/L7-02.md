# L7-02: Scroll persistence clears a recoverable selection error

Status: **OPEN**, blocking QUA-01 and PORT-09. Owner: `@itrocks/property-select` browser view.
Tested source: `11375222ec8ba44ddca3faf09419ee3e465bf76d`; runtime 0.7.1, tracking/tests 0.7.2.

## Reproducer and evidence

Use the L7 owned application recipe in [the report](../reports/L7.md), then run:

```bash
node node_modules/@itrocks/property-select/docs/orchestration/environment/checks/L7-error.mjs
```

In a real 844 × 390 Chromium viewport, open the pane, visit delivery address, return to root, then click `note`.
Playwright aborts only its actual column-value HTTP request. Native clicking scrolls the property into view.
Expected: The rejected addition retains a visible recoverable error while leaving the context and columns intact.
Observed in three independent contexts: `Failed to fetch` appears, then is erased after 3.6–6.4 ms.
At 600 ms the message is empty, no note column exists and root navigation remains usable.
[Raw status mutation observations and screenshots](../evidence/L7/error/results.json).
The complete L7 itinerary also reproduces this at its landscape step.

## Diagnosis and correction boundary

`PropertySelectView` writes the consumer error to `.ps-status`. Its ordinary `render()` clears that status whenever
controller status is ready. Scrolling saves the position; asynchronous `flushState()` emits another change and render
clears the error. Preserve an actionable error through unrelated state/scroll updates, clearing it on an appropriate
new user operation or recovery. Keep loading/search/persistence messages and controller ownership coherent.
Add regression coverage with a real browser and retain the visible-error assertion; do not delay away or waive it.
No new feature or persistence API is required. Independent [RETEST-L7-1](../tasks/RETEST-L7-1.md) must close the defect.
